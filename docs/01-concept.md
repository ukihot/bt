# 1. コア体験

出典: `CLAUDE.md` §1, §2, §8

## ジャンルと題材

文字だけのPCゲーム。日本語のみ、グラフィック・罫線・絵は一切なし。パン屋の作業ログが画面に流れ
続けるだけの、「抽象タワーディフェンス × 謎解き × 和ホラー」。テーマは魔除け。

## 体験のコア

**「このログ、誰が書いてるんだ?」を確かめる体験。**

- プレイヤーは業務ログを検分し、混入する「異常な筆」を見抜いて対処する
- 恐怖のピークは「分かった瞬間」ではなく「**もう遅いと悟った瞬間**」
- 最重要のゾクッは、内容ではなく**筆癖**で異常に気づいてしまう瞬間
  (内容は正常なのに、数え方・表記だけが店の癖と違う)
- 目は1つ、画面は3つ。操作できるのは1つだけで、それでも残り2つから目を離せない構造が、
  恐怖とタワーディフェンスの両方の土台になる

## 絶対原則(和ホラーの文法)

実装・テキスト生成のすべてがこの5原則に従う。

| # | 原則 | 意味 |
|---|---|---|
| 1 | 説明しない | 脅威の正体・理由・由来は最後まで一切開示しない。種明かし・どんでん返し禁止 |
| 2 | 距離だけが縮む | 日を追って外は不穏に、売り場のルール変更は激しく、焼成室はより追い詰められる。最後は画面の外(帳場=プレイヤー自身)へ寄る |
| 3 | 理不尽な作法 | 対処法は民俗的な禁忌として存在するが、理由は永遠に不明 |
| 4 | 触れることが穢れ | 誤った接触はプレイヤー自身への「障り」として返る |
| 5 | 終わらない | クリアしてもカタルシスなし。除霊完了は存在しない |

## 禁止事項(実装・テキスト生成時)

- グラフィック・罫線・アイコン・色による強調(文字のみ。強調も文体で行う)
- 脅威の正体の説明、ネーミングによる正体の示唆
- ジャンプスケア的な演出(音・点滅)
- チュートリアル、目標表示、正解/不正解の明示的なUI通知
- 勝利演出、エンディングの解決感
- 派手な文字化け(例外: CRT的な環境ノイズとしての一文字グリッチのみ。[05-threats-and-tells.md](05-threats-and-tells.md) 参照)

これらは単なる方針ではなく、実装のガードレールとして機能している。例えば `resolve()` の
戻り値には勝敗を明示する概念が存在せず(`Outcome { corruption, income, zone_bump }` の3値のみ)、
UIにも侵食度の数値やスコアは一切表示されない(`src/screens/playing/render.rs` 参照)。
